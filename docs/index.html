Sports Booking

Book sports courts by the hour, with no double bookings, even when many people book the same slot at the same moment.

How it works

A customer searches for padel courts in Varna, picks a free hour, which holds it for 10 minutes, and confirms.

This page is a static overview: GitHub Pages cannot run the Java server and database. To book for real, run it locally with one command (below) or use the live demo link when it is available.

The hard part: one slot, sold once

Two people can click the same evening slot in the same millisecond. Checking "is it free?" in Java and then saving is not safe: both requests can pass the check before either saves. So PostgreSQL enforces the rule itself, with an exclusion constraint on time ranges:

CONSTRAINT booking_no_overlap EXCLUDE USING gist (
    court_id WITH =,
    tstzrange(start_time, end_time, '[)') WITH &&
) WHERE (status IN ('HELD', 'CONFIRMED'))

A load test found a second problem: simultaneous inserts could deadlock while checking the constraint. Each booking transaction now locks the court row first, so requests for one court queue up and the losers get a clean 409 SLOT_UNAVAILABLE, while other courts keep booking in parallel.

Features

  • Search free slots by city, sport and day
  • Hold for 10 minutes, then confirm; a scheduled job releases unconfirmed holds
  • Free cancellation until 24 hours before; managers can cancel any time and the customer is emailed
  • Weekly bookings that report the weeks that clash
  • Customer, manager and admin roles; managers only see their own facilities
  • REST API with JWT, OpenAPI docs and RFC 9457 problem-detail errors

Design at a glance

Double bookingsPostgreSQL exclusion constraint plus a per-court row lock
State changesOptimistic locking with a version column, so a stale confirm loses to the expiry job
TimeStored in UTC, shown in the facility's time zone; every rule uses an injected clock
SecurityStateless JWT for the API, session and CSRF for the site, @PreAuthorize on services
SchemaFlyway migrations; Hibernate only validates
EmailSent after the transaction commits, on another thread
QualitySpotless, Checkstyle, JaCoCo; GitHub Actions runs everything on every push

Run it yourself

Needs Java 25 and Docker. PostgreSQL and a mail catcher start automatically.

git clone https://github.com/KALalev18/sports-booking.git
cd sports-booking
./mvnw spring-boot:run
# open http://localhost:8080 and log in as customer@example.com / demo1234

Without Java: docker compose --profile app up --build.
